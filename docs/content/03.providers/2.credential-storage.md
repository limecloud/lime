# Provider 凭据存储

Desktop、CLI 和 App Server 使用相同的 Provider 凭据 owner。数据库只保存随机引用，原始 API Key 不作为密文伪装后保存在数据库中。

`LIME_HOME` 指定凭据根目录，未设置时为用户目录下的 `.lime`。`LIME_CREDENTIALS_STORE` 在进程启动时读取：

| 值                 | 行为                                                                                                                                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未设置或 `keyring` | 默认模式。使用 Codex 的 secrets/keyring 实现：随机口令保存在 OS 密钥库，凭据加密到 `secrets/local.age`。macOS 使用 Keychain，Windows 使用 Credential Manager，Linux 使用系统 Secret Service/keyutils 适配。密钥库不可用则报错，不自动切换存储。 |
| `file`             | 显式的 headless 模式。每条凭据写入 `credentials/API_KEY_<随机ID>.json` 明文文件；Unix 创建为 `0600`，Windows 限制当前用户 ACL。仅在受控的用户目录中使用，妥善保护备份。                                                                         |

例如，在没有可用桌面密钥库的独立 CLI 环境中：

```bash
LIME_HOME="$PWD/.lime-headless" LIME_CREDENTIALS_STORE=file lime
```

PowerShell：

```powershell
$env:LIME_HOME = Join-Path $PWD ".lime-headless"
$env:LIME_CREDENTIALS_STORE = "file"
lime
```

同一数据库的 Desktop、CLI 和 App Server 必须使用相同的目录与模式。改变环境变量不会迁移现有凭据；切换前在原模式删除 Key，再在新模式重新添加。旧 XOR 凭据不再读取，请在设置中删除旧条目并重新录入。Provider 身份、多 Key 轮询、模型和协议配置保持原有语义。

共享 age 文件的读改写和 keyring 初始化通过同一个进程锁串行执行；锁等待最多十五秒，覆盖真实平台上可能超过三秒的 scrypt 读改写，锁文件不删除。文件模式同样参与锁定。锁定、权限、读取或持久化错误均明确返回，不回退到其他凭据来源。

数据库与密钥库是两个独立存储，不能形成跨存储原子事务：新增数据库写入失败时补偿删除新 secret；删除/替换在数据库提交后清理旧 secret，清理失败会报错。进程在两步之间崩溃可能留下无引用的 secret。备份与恢复必须同时考虑数据库、凭据目录和 OS 密钥库；只复制 age 文件不能恢复其解密口令。

该默认选择是 Lime Provider 的明确差异。Codex 的 CLI 登录凭据默认采用 File；Grok-build 的账号凭据采用权限保护的明文文件；不将本实现宣称为二者默认行为相同。
