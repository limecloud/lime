# MCP 工具扩展

::alert{type="info"}
MCP 属于进阶能力，当前仍应按实验功能理解。它不会替代 Lime 的主创作路径，更适合已经明确需要外部工具或资源接入的场景。
::

当前 Lime 已提供 MCP 服务器管理与运行时浏览面板。你可以集中维护服务器配置，把它同步到常用外部工具，并在 Lime 内验证可用的 Tools、Prompts 和 Resources。

## 当前可做的事

- 新增、编辑、删除 MCP 服务器配置
- 使用预设快速创建常见服务器
- 从 Claude、Codex、Gemini CLI 导入已有 MCP 配置
- 将当前配置同步回外部应用
- 查看服务器运行状态并手动启动、停止
- 浏览运行中服务器暴露的 Tools、Prompts、Resources

## 一个最小配置示例

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/workspace"],
  "env": {}
}
```

如果你只是想先验证链路，`filesystem` 是最容易起步的示例。

## 免费网页搜索与提取：Parallel Search MCP

[Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp) 提供 `web_search` 网页搜索和 `web_fetch` 网页内容提取。匿名搜索使用 Fast 模式，无需注册账户或配置 API Key，适合轻量研究；免费端点有速率限制。

在设置的 MCP 配置页新建服务器，选择「自定义」，将名称设为 `parallel-search`，并把以下 JSON 粘贴到服务器配置编辑器：

```json
{
  "transport": "streamable_http",
  "url": "https://search.parallel.ai/mcp",
  "http_headers": {
    "User-Agent": "Lime (https://github.com/limecloud/lime)"
  },
  "tool_timeout": 60
}
```

保存并仅在 Lime 内启用，然后在 MCP 运行时面板启动服务器。连接成功后，Tools 列表应显示 `mcp__parallel-search__web_search` 和 `mcp__parallel-search__web_fetch`。不需要填写环境变量、Bearer token 或执行 OAuth 登录；请使用 `/mcp`，`/mcp-oauth` 需要认证。

`web_search` 的最小调用参数：

```json
{
  "objective": "查找 Model Context Protocol 的官方介绍",
  "search_queries": ["Model Context Protocol official introduction"]
}
```

`web_fetch` 的最小调用参数：

```json
{
  "urls": ["https://modelcontextprotocol.io/docs/getting-started/intro"],
  "objective": "提取 MCP 的用途与连接方式"
}
```

搜索结果包含来源链接和正文摘录，网页提取返回对应页面的内容摘录。工具执行由工作区的真实 Thread 承接，设置页用于管理配置和浏览能力。连接失败时先检查服务器状态与错误信息；遇到速率限制时按服务返回的重试提示等待。

## 推荐使用流程

1. 先选择一种来源

- 直接新建服务器配置
- 从 Claude、Codex、Gemini CLI 导入已有配置

2. 再决定同步范围

- 只在 Lime 内启用
- 或同步到 Claude、Codex、Gemini CLI 一起使用

3. 保存后验证运行状态

- 确认服务器能正常启动
- 确认 Lime 能读取到对应能力列表

4. 最后做小范围试跑

- 先试一个简单 Tool
- 再验证 Prompt 或 Resource 是否符合预期

## 当前常见入口

当前面板已经内置一些常见预设，适合快速起步：

- `Filesystem`
- `GitHub`
- `PostgreSQL`
- `自定义`

如果团队已有现成配置，优先导入；如果只是单机试验，优先从最小自定义或 `Filesystem` 开始。

## 安全边界建议

1. 只给服务器开放必要目录、数据库或环境变量
2. 新接入的 MCP 先在测试目录验证，不要直接连生产数据
3. 对外同步前，先确认对应应用确实需要这台服务器
4. 涉及密钥时，避免把敏感值直接写进会提交的公共配置

## 排错顺序

1. 先看服务器配置 JSON 是否有效
2. 再看服务器是否能成功启动
3. 再看 Tools、Prompts、Resources 是否已被正确发现
4. 最后再检查具体调用参数、环境变量和外部依赖
